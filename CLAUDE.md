# CLAUDE.md

Guidance for AI assistants (Claude Code and others) working in this repository.

## What this repo is

**AI Notes** is a curated knowledge base of notes on the state of the art in AI,
with a focus on generative and large language models. It is the "raw material"
for the [Latent Space](https://www.latent.space/) / [lspace.swyx.io](https://lspace.swyx.io/)
newsletter. (Originally `sw-yx/prompt-eng`, renamed as the focus shifted from
prompt engineering to AI engineering.)

This is **content, not code** — there is no build, no application, and no tests.
The deliverable is well-organized, well-linked Markdown. The repo is also an
**Obsidian vault** (`.obsidian/` is gitignored), so notes use Obsidian
conventions: `[[wikilinks]]` between notes, embedded images, and folders as
topic groupings.

## Repository layout

Top-level Markdown files are the primary, actively-maintained topic notes:

```
README.md          High-level overview of the space + auto-generated TOC
TEXT.md            Text generation (mostly GPT-4 class models)
  TEXT_CHAT.md     ChatGPT, competitors, derivative products
  TEXT_SEARCH.md   Semantic search / retrieval with LLMs
  TEXT_PROMPTS.md  Swipe file of good text prompts
IMAGE_GEN.md       Image generation (heaviest coverage: Stable Diffusion, etc.)
  IMAGE_PROMPTS.md Swipe file of good image prompts
AUDIO.md           Audio / music / voice — transcription + generation
CODE.md            Code-generation models (Copilot, etc.)
INFRA.md           AI infrastructure, hardware, scaling
Software 3.0 stack.md   The AI-native software stack

Resources/         Standing, cleaned-up references meant to be permalinked
                   (BENCHMARKS.md, DATASETS.md, Finetuning.md, funding, …)
Monthly Notes/     Dated monthly recaps (Monthly Notes/, 2024 notes/, 2023 notes/)
                   Each new month follows "MONTHLY TEMPLATE.md"
stub notes/        Lightweight proto-pages for future coverage areas
                   (RAG.md, AGENTS.md, EVALs, RLHF, etc.) + Event Notes/
blog ideas/        Potential blog post drafts derived from these notes
```

## Conventions

- **Format:** GitHub-flavored Markdown that also renders in Obsidian. Prefer
  concise bullet points with links over prose. Each entry is typically a link
  plus a short annotation of why it matters.
- **Growth model:** a topic starts as a page in `stub notes/`, then graduates to
  a top-level file (or a `Resources/` page) once it has enough substance.
  `Resources/` pages are the "cleaned up, permalink-worthy" tier.
- **Monthly notes:** create a new file in `Monthly Notes/` for the current month
  by copying the section headings from `MONTHLY TEMPLATE.md` (Themes and Memes,
  OpenAI news, Models, Papers, Fundraises and Milestones, AI Eng Tooling, Agents,
  Useful learning, Misc).
- **Linking:** use standard Markdown links for external URLs; Obsidian
  `[[wikilinks]]` are used for cross-references between notes in the vault.
- **Images:** stored at the repo root (e.g. `Pasted image ...png`) as Obsidian
  pastes them. `.obsidian/` config is intentionally gitignored.

## The auto-generated table of contents

The README's Table of Contents (and the per-file TOCs) are generated by
[`doctoc`](https://github.com/thlorenz/doctoc) / a toc-generator GitHub Action —
**do not hand-edit** the region between these markers:

```
<!-- START doctoc generated TOC please keep comment here to allow auto update -->
<!-- DON'T EDIT THIS SECTION, INSTEAD RE-RUN doctoc TO UPDATE -->
...
<!-- END doctoc generated TOC please keep comment here to allow auto update -->
```

`.github/workflows/toc.yml` runs `technote-space/toc-generator` daily (12:00 UTC)
and on manual dispatch to regenerate TOCs for all `*.md` files
(`MAX_HEADER_LEVEL: 3`, folding enabled). To refresh locally you can run doctoc,
but it's simplest to let the Action do it — just edit headings and let the TOC
update itself. When adding content, edit real headings/sections, not the TOC.

## How to help here

- **Adding notes:** put content under the right topic file or `stub notes/` page,
  keep entries link-first with a one-line "why it matters," and match the
  surrounding bullet style.
- **Do not** reformat large sections, rewrite others' annotations, or touch
  doctoc regions unless asked.
- There is nothing to build or test — the "check" is that Markdown renders
  cleanly and links resolve.
- Content licensing: notes are MIT-licensed (see `LICENSE`); external links and
  quotes belong to their authors.
